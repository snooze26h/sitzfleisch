# 菜单栏显示稳定性排查

用户反馈整个 S 图标、项目名和倒计时会不定时消失再出现。两张截图不能确定触发条件，本轮没有捕捉到整项消失的现场，因此不将下面的宽度修正表述为已彻底解决全部偶发现象。

## 已确认

- 当次进程检查只有一份坐功，未匹配到 Ice、Bartender、Hidden Bar 等常见菜单栏管理工具。
- 项目只在启动时创建托盘，未发现反复隐藏、销毁或创建图标的调用；原实现每次状态推送都会重设标题和提示。
- 所用 tray-icon 0.24.2 使用自动宽度的 NSStatusItem，set_title 直接设置普通文本，未为倒计时指定等宽数字。
- 在 macOS 26.6.2 上，使用原生 AppKit 对「浏览 21:00」至「浏览 21:59」测量：默认 13pt 菜单字体宽 58.7928–63.4647pt，差值 4.671875pt；13pt 等宽数字系统字体均为 65.6102pt，差值 0。该测量使用独立字体对象，不是对旧进程菜单栏消失瞬间的捕获。

## 修改

- macOS 托盘初始化时设置系统等宽数字字体，沿用原控件字号与原项目名、倒计时格式。
- 创建托盘时即设置标题和提示，避免先出现仅图标状态再补标题。
- 相同标题不重复调用原生 setter；更新失败时不写入缓存，后续仍可重试。
- 原生 UI 调用前释放缓存锁，保持菜单按实际状态变化更新的既有逻辑。
- AppKit 桥接仅在 macOS 编译；Tauri 约束到当前 2.11 小版本，以维持原生托盘类型兼容。

## 后续：暂停后不显示

用户进一步给出了「暂停」这个触发条件。当前主窗口和存档都显示「浏览」已暂停，应用仍在正常心跳；源码没有暂停时隐藏托盘的分支。

- 上一版只稳定了数字宽度，但暂停标题仍从 `浏览 28:00` 增长为 `浏览 暂停 01:35`。同一 13pt 系统等宽数字字体下，文字宽度由 65.6102pt 增至 94.9879pt，多占约 29.38pt。
- [Apple 的 NSStatusItem 文档](https://developer.apple.com/documentation/appkit/nsstatusitem/isvisible)说明：空间不足时系统可能临时隐藏整项，且此时 `isVisible` 仍可能为真。因此仅调用显示接口或检查该属性，不能证明屏幕上实际可见。
- 这条宽度变化与用户给出的触发条件相符，但仍未捕获系统挤掉图标的瞬间，不将推断写作已证实的唯一根因。
