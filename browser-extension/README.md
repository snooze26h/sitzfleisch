# 坐功浏览器扩展

按完整网址或域名屏蔽网页，适用于 Chrome / Edge 120 及以上版本。整站规则由系统 hosts 与此扩展共同执行，完整网址规则由此扩展执行。

## 安装与使用

1. 启动包含完整网址屏蔽功能的坐功主程序。
2. Chrome 打开 `chrome://extensions`，Edge 打开 `edge://extensions`，开启「开发者模式」。
3. 点击「加载已解压的扩展程序」，选择此 `browser-extension` 文件夹。每个浏览器、每个用户资料都需单独安装。
4. 在坐功的「设置 → 网站屏蔽」相应区域添加精确网址或整站域名，再开始学习日。点击扩展按钮查看连接和两类规则数量。整站需更新主程序与扩展，并确认「浏览器已同步」。
5. 学习日暂停、休息、主程序退出都保持已同步的规则。收工或放弃今天后，保持主程序运行，等待同步或点击「立即同步」。阻止页会回到原网址，刷新阻止页也会检查最新状态。
6. 阻止页的「返回上一页」会打开此标签最近访问的未屏蔽网址，避免退回屏蔽网址后再次被拦。若没有已知可用页，或返回目标也已被屏蔽，则打开空白页。「打开空白页」始终提供独立出口；「检查收工状态」会显示检查中、仍在学习日或连接失败的结果。

使用此目录无需额外构建或依赖安装。更新代码后，在扩展管理页点击重新加载。

## 精确匹配示例

| 添加的规则 | 屏蔽 | 仍然放行 |
| --- | --- | --- |
| `https://www.douyin.com/?recommend=1` | 完全相同的推荐入口 | `https://www.douyin.com/user/self?from_tab_name=main&showSubTab=video&showTab=favorite_collection` |
| `https://www.bilibili.com/` | B 站首页 | `https://www.bilibili.com/video/BV1234567890/` |

使用浏览器的 `new URL(...).href` 规范化后逐字比较：协议和主机名按浏览器规则处理，默认端口和空路径也按浏览器标准处理；不删 `www.`，不改路径、参数或片段的大小写，不调整参数顺序，不忽略 `#...`，不匹配前缀或子路径。空查询符 `?`、空片段符 `#` 也保留。协议不同、参数变化或多一个尾斜线可能是另一条规则，应分别添加。

**如果仍有 `douyin.com` / `bilibili.com` 等整站规则，同站收藏和学习视频仍会被屏蔽。** 请先通过主程序移除该站的整站规则，再使用完整网址规则。扩展按网址区分页面，不识别视频是娱乐还是学习内容。

整站规则 `live.bilibili.com` 会覆盖直播首页与 `/123456?from=…` 等所有房间入口，同时覆盖 `www.live.bilibili.com`；不扩大到 `www.bilibili.com`、`space.bilibili.com` 或其他子域。浏览器层只比较域名，不依赖目标网站是否重新经过系统 DNS，因此会检查使用代理或旧连接打开的页面。域名尾部的 DNS 根点不影响整站匹配。超长或带凭据的网址只显示通用拦截页，收工后需自行重新打开原页面。

## 同步与边界

- 扩展每 30 秒尝试同步，并在页面导航、SPA 路由或片段变化、标签激活以及浏览器启动时同步。成功同步后也检查已打开的标签。
- Chrome 的闹钟可能因休眠或调度延后，因此 30 秒是请求周期，不是严格的实时保证。唤醒后打开页面或点击「立即同步」可触发检查。[Chrome alarms 文档](https://developer.chrome.com/docs/extensions/reference/api/alarms)
- **这是导航监听后的页面拦截，页面可能短暂显示、播放声音或发出网络请求后才被替换。** 使用 `webNavigation` 覆盖普通导航、`history.pushState` 和 hash 变化；不使用无法逐字匹配 URL 片段的网络规则。它不是内容过滤器，也不保证阻止网页发出网络请求。[Chrome webNavigation 文档](https://developer.chrome.com/docs/extensions/reference/api/webNavigation)
- 第一次成功同步前无法拦截。同步成功的规则保存在浏览器本地，断开主程序、扩展 worker 重启或浏览器重启都不会清除缓存；离线时无法获知主程序的收工状态。
- 只处理浏览器顶层页面。内嵌 iframe、其他浏览器、Safari、桌面客户端不在此扩展范围内；无痕窗口需用户在扩展管理页单独允许。
- 地址栏会随网站跳转发生变化。精确规则不会自动扩大范围，实际要屏蔽的另一个入口应另行添加。阻止页不提供学习中临时放行按钮。

## 本地通信与权限

扩展只读取 `GET http://127.0.0.1:47832/v1/rules`。请求保留 `X-Sitzfleisch-Client: browser-extension-v1`，增加 `X-Sitzfleisch-Protocol: 2` 协商整站支持；应用规则成功后的下一次请求增加 `X-Sitzfleisch-Applied: <revision>`。新版响应格式：

```json
{"protocol":2,"active":true,"urls":["https://www.douyin.com/?recommend=1"],"hosts":["live.bilibili.com"],"revision":"0123456789abcdef"}
```

响应逐项校验协议、类型、版本号、两类规则合计条数（最多 64 条）、网址长度（每条最多 4096 UTF-8 字节）、HTTP(S) 协议和凭据；域名必须为合法规范化域名，拒绝 IP、端口、通配符和 URL。无效响应不会替换现有规则。请求超时为 3 秒，并发请求合并，失败不会报告已同步。

未携带协议头的老扩展继续收到不含 `hosts` 的 v1 响应，其精确网址和收工同步不受影响；主程序会提示其尚不支持浏览器整站拦截。新版扩展也能读取旧主程序的 v1 响应，但会提示更新主程序；已有整站缓存不会被学习日中的旧协议覆盖，明确收工仍可解除。

- `storage` 保存规则缓存，`alarms` 触发同步，`webNavigation` 监听路由，`tabs` 在跳转前核对当前网址并打开阻止页。
- 主机权限仅为 `http://127.0.0.1/*`，用于从扩展 worker 读取本机服务；不注入内容脚本，不申请任意网站内容权限。[Chrome 扩展跨源请求文档](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests)
- 不上传、归档浏览记录。发给主程序的数据只有固定客户端标识、协议版本和已应用版本号。每个标签仅在 worker 内存中保留最近一个已访问的未屏蔽网址，标签关闭后清理；阻止时将它与原网址一起放在当前阻止页片段中，以便 worker 重启后仍可返回。未提交的导航不作为返回目标；不申请浏览历史权限。
- 本机端口服务只提供规则读取，不修改设置。协议头不是身份认证，其他本机客户端（包括其他登录账号）也可读取生效网址；接口不提供计时记录或浏览记录。若其他程序占用该端口，扩展会显示等待连接或缓存状态。

## 验证

在仓库根目录执行：

```sh
node --test browser-extension/*.test.mjs
```

测试直接使用生产 worker、阻止页控制器和模拟 Chrome API，覆盖整站匹配、已打开直播间替换、域名边界、旧协议兼容、整站缓存与解除，以及精确匹配、普通及 SPA 导航和返回、无历史出口、返回目标被屏蔽、已开标签、旧导航竞争、学习日启停、缓存重启、损坏响应、请求超时及应用失败。

此前的精确网址版本在临时独立 Chrome 配置中加载真实扩展，以测试响应替代网页和主程序规则接口，验证了推荐拦截、收藏与视频放行、SPA 跳转、参数和片段差异、返回收藏、离线缓存与收工恢复。这些证据不等同于用户真实登录页面或 Edge 的端到端验收；安装后应在学习日内核对实际使用的入口。
