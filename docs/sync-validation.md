# 跨设备同步交付与验证（2026-10-27）

## 已实现

- Supabase 邮箱验证码登录、刷新与仅退出当前设备的会话；访问/刷新令牌保存在 macOS Keychain、Android Keystore 或 Windows DPAPI 中，不进入界面、普通存档或日志。
- 同账号项目、计划、当前学习日、暂停/继续/延长/结束、完成记录及历史共享；前台短轮询、操作后唤醒、离线待上传和恢复前台补拉。
- 云端按账号隔离、事务版本比较和操作幂等；网络发送期间继续操作不会被旧确认清掉，重启保留未确认请求。
- 账号独立存档、迁移预览、恢复副本、退出回到单机数据；设备偏好不上传，切换账号时仍保留本设备最新设置。
- 历史和计时使用稳定 ID，避免同秒记录误操作；确认框和托盘操作绑定账号及目标计时，完成笔记核对原内容。
- 共享计时采用包含睡眠的连续时钟与服务端锚点，保存有效校准偏移；校时从最后一次业务草稿重建投影，不重复累计。安卓在系统提醒边界转换回设备时钟。
- 未配置云服务的构建继续提供单机模式；已有数据没有被读取、迁移或上传。

实现约定见 [sync-design.md](sync-design.md)，实际启用步骤见 [sync-deployment.md](sync-deployment.md)。

## 2026-11-02 独立审查后的修复

依据独立审查结论（审查报告留在本地，未入库）修复以下问题；行为约定已同步到 [sync-design.md](sync-design.md)。

- 容量：投影、合并与本机账号存档只校验结构，体积上限只约束上传。新操作在上限以下 64 KiB 处停止，余量留给自然到时与合并；超过时只拒绝让文档变大的操作，删除旧记录仍可进行。此前文档接近 2 MiB 时，一次自然到时就会让投影越限，冲突无法解决，重启后所有设备无法操作也无法退出。账号页在占用 90% 起提示清理；按每天 8 格的合成数据，约 400 天达到上限。
- 合并：学习日按稳定 ID 逐条比较。此前一端收工、另一端收工后又新开的一天会被当成同一个“当前学习日”冲突，选“本机”即丢掉另一端的新学习日。两端各开了不同学习日时，未选的一天按合并时刻收工归档。冲突说明同步修正。
- 单机保护：只有已选账号的存档读不出来时才暂停保存；从未登录的设备遇到同步目录权限或设备标识问题仍按单机使用。暂停保存时账号页提供退出账号的出口，账号文件原样保留。单机存档损坏不再阻止打开或重新登录已有账号。
- 被拒请求：云端返回 400/413 的写请求不再原样无限重试，内容改变或手动重试时用新操作编号上传；发送期间已修正的内容立即重试。数据库文本校验改用明确码点，见新迁移 `202611020001_locale_independent_text.sql`；此前 glibc 的 `C.UTF-8` 会把客户端接受的 U+2028/U+2029 判为控制字符。
- 资源：同步轮询没有新内容时不再重写账号存档、不推完整历史；账号存档不再重复保存历史；同步状态只在文档变化后重算；账号模式的心跳定期保存由 30 秒改为 5 分钟。365 天合成数据下，单次 `equivalent` 由约 34 ms 降到约 10 ms（release），且不再每秒执行。
- 会话与确认：RPC 返回 401 时先刷新一次会话；刷新后的会话写入安全存储失败时保留在内存并在下一轮补写，不退回已经作废的旧刷新令牌。退出登录在本机退出完成后才撤销远端会话。收工与放弃学习日的确认框不再因打开时那一格自然到时或休息结束而失效。

验证：核心 137 项、外壳 122 项、数据库 16 项、扩展 64 项通过；同步界面、屏蔽规则、快照乱序脚本、TypeScript、前端打包、两个 crate 的 Clippy（含 Android ARM64 目标）和 `git diff --check` 通过。新增回归覆盖：越限投影仍可应用与合并、捕获余量与缩小操作、两种新学习日合并、客户端与数据库同一组文本样例、被拒请求的释放与重试、状态缓存、同步目录不可用时的单机模式、账号存档不含重复历史、收工确认的自然到时。

尚未完成：新迁移需在真实 Supabase 项目中执行（未连接或修改云端）；当前安装的 Mac 与手机仍是旧版本。真实数据库的区域设置、双设备实机接力、钥匙串/Keystore 实际失败路径、Windows 原生运行，以及网络编排中刷新与被拒处理的端到端行为（需应用句柄，未做自动化）仍待验收。
