# 跨设备同步交付与验证（2026-10-27）

## 已实现

- Supabase 邮箱验证码登录、刷新与仅退出当前设备的会话；访问/刷新令牌保存在 macOS Keychain、Android Keystore 或 Windows DPAPI 中，不进入界面、普通存档或日志。
- 同账号项目、计划、当前学习日、暂停/继续/延长/结束、完成记录及历史共享；前台短轮询、操作后唤醒、离线待上传和恢复前台补拉。
- 云端按账号隔离、事务版本比较和操作幂等；网络发送期间继续操作不会被旧确认清掉，重启保留未确认请求。
- 账号独立存档、迁移预览、恢复副本、退出回到单机数据；设备偏好不上传，切换账号时仍保留本设备最新设置。
- 历史和计时使用稳定 ID，避免同秒记录误操作；确认框和托盘操作绑定账号及目标计时，完成笔记核对原内容。
- 共享计时采用包含睡眠的连续时钟与服务端锚点，保存有效校准偏移；校时从最后一次业务草稿重建投影，不重复累计。安卓在系统提醒边界转换回设备时钟。
- 未配置云服务的构建继续提供单机模式；已有数据没有被读取、迁移或上传。

实现约定见 [sync-design.md](sync-design.md)，实际启用步骤见 [sync-deployment.md](sync-deployment.md)。

## 尚未验证与启用依赖

- 尚无真实 Supabase 项目：没有创建账号、部署数据库、发送真实验证码或上传个人数据。PGlite 不替代真实 Auth、SMTP、API 网关或 PostgreSQL 多连接竞争验收。
- 未做本轮真实 Mac/安卓双设备联网、合盖、锁屏、后台冻结与通知投递验收；计时接力与睡眠跨度目前是隔离合成验证。
- Keychain / Keystore / DPAPI 只做相应编译和输入边界验证，没有读写实际用户会话；Windows 本轮未进行原生运行验收。
- 安卓后台即时到达受系统调度限制；恢复前台补拉是首版保证的路径。当前不接入后台推送。
- 开启功能需要按部署说明创建 Supabase 项目、安装迁移、配置邮箱验证码，再用同一项目的 URL 和公开密钥重建两端应用。客户端不得配置 service_role、secret key、数据库或邮件口令。
- 共享文档最多 2 MiB、历史最多 1000 个学习日、删除标记最多 10000 个；超限拒绝写入并保留数据。

本次没有安装或替换用户现有应用，没有提交或推送 Git。代码改动与部署文件保留在工作区。
