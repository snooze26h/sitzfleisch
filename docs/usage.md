## 安装

从 [Releases](https://github.com/snooze26h/sitzfleisch/releases/latest) 下载对应系统的安装包。

### macOS

下载通用版 `.dmg`，打开后将 Sitzfleisch 拖入「应用程序」。同一个安装包适用于 Apple 芯片和 Intel Mac。

当前版本没有 Developer ID 签名与公证。如果提示无法验证开发者，确认安装包来自本仓库后，可在尝试打开应用后进入「系统设置 → 隐私与安全性」，点击「仍要打开」，再确认打开。参见 [Apple 的打开说明](https://support.apple.com/zh-cn/102445)。

若提示「已损坏」，先重新下载并确认来源；这条提示也可能表示文件确实损坏或被修改。确认文件可信且完整、仍无法打开时，可针对本应用移除下载隔离标记：

```bash
xattr -dr com.apple.quarantine /Applications/Sitzfleisch.app
```

### Windows

下载 `-setup.exe` 并运行。若 SmartScreen 提示拦截，确认安装包来源后，可点击「更多信息 → 仍要运行」。Windows 版尚未完成真机验收，遇到问题可[提交 Issue](https://github.com/snooze26h/sitzfleisch/issues)。

### Android

从 Releases 下载 `Sitzfleisch_<版本>_android-arm64.apk`。

- 支持 Android 8.0 及以上的 ARM64 设备。用手机浏览器下载安装包，按系统提示允许该浏览器安装未知应用；确认来自本仓库，并用同名 `.sha256` 核对文件完整性后安装。
- 升级时直接用新版安装包覆盖安装，记录保留。**卸载会删除手机上的全部记录**；坐功不把记录备份到云端。「坐功·测试」是开发用的调试包，和正式包是两个应用，记录各自独立。
- 首次按「开始今天」时允许通知。荣耀等系统默认不让新应用弹出横幅，到点只会响铃：进入「设置 → 提醒」，按提示为计时、身体提醒和喝水打开横幅。提醒的声音与振动由系统通知设置管理。
- 荣耀手机进入「设置 → 应用和服务 → 应用启动管理」，关闭坐功的自动管理，允许自启动、关联启动和后台活动。保持自动管理时，从最近任务里划掉坐功会被系统强行停止，之后的提醒都不会响；改为手动管理后，划掉也能按时提醒。其他系统按应用内的后台引导设置。

手机锁屏或应用进程被普通回收后继续按墙钟计时，实际走完的格完整计入，休息从真实终点开始；不会把这段时间当作自动暂停。手机按系统时间计时，手动把系统时间往前调，坐功会当作真的过了这么久。桌面版仍使用下文的心跳中断规则。

喝水提醒只在学习日内按整点、半点发出。未收工、本次暂停满 2 小时后，不再发喝水和「还没开格」提醒；开下一格或继续这一格后恢复。起身提醒仅在格运行时排程，喝水、起身和暂停提醒可分别关闭。

**手机重启后，打开一次坐功才能恢复未来提醒；已经错过的提醒不补发。** 在系统中「强行停止」后也需要重新打开。

手机不提供网站屏蔽、浏览器扩展、桌面托盘或开机自启功能；可以改用下面的应用屏蔽。手机和电脑的数据各自在本机保存，不自动同步；首次使用需在手机上设置项目和目标。

记录存于应用私有目录中的 `state.json`，普通文件管理器不能直接访问。返回键依次关闭弹层、退出设置分区、回到今天，再把应用退到后台；退到后台保留状态。历史页支持展开明细和复制 Markdown。

### 应用屏蔽（Android）

在「设置 → 应用屏蔽」里点「添加应用」选好要屏蔽的应用，再打开「屏蔽名单里的应用」。开着的时候，打开名单里的应用会先回到桌面、再回到坐功，并提示是哪个应用被拦下。这个开关与学习日无关：没开始今天也能打开，收工也不会自动关闭；没有临时放行。

- 第一次打开时，按提示到系统的无障碍设置里打开「坐功应用屏蔽」。它只订阅窗口切换、读取前台应用的包名，不读取屏幕内容，不代你点按，也不联网。
- 用浏览器下载安装的坐功，系统可能把这项开关标为「受限设置」而无法打开：到坐功的「应用信息」页，点右上角 ⋮，选「允许受限制的设置」，再回去打开。菜单名称以手机实际显示为准。
- 荣耀等系统限制应用读取应用列表。选择单只列出一部分应用时，点「允许读取」；系统不再弹出授权时，到应用信息的权限里打开「获取应用列表」。
- 关掉开关，或在开着时把应用移出名单，都要先停一下、再手动输入一次应用名或「关闭屏蔽」。桌面、系统设置、拨号和坐功自己永远不会被屏蔽，也不会出现在选择单里。
- 坐功被「强行停止」后，系统会同时关掉它的无障碍服务，屏蔽随之失效；今天页会提示「应用屏蔽没生效」，需要再打开一次。按上文的后台设置管理坐功，并在最近任务里锁定它。
- 按应用拦截，不区分应用里的页面；拦截发生在应用打开之后，可能先闪一下。悬浮窗、画中画等不是应用界面的窗口不拦。

## 每天怎么用

1. **安排今天**：在开始页调整各项目的目标分钟数，再按「开始今天」。设为 0 的项目当天不安排。
2. **开始一格**：选择项目，直接输入 1–180 的整数分钟，或用加减按钮每次调整 1 分钟，再选择之后的休息时长。这里选的休息只管这一格（选「不休息」就是这一格之后不休息），默认值在「设置 → 节奏」。无需提前填写任务计划。
3. **按需调整**：可以暂停 / 继续，点击「延长…」自行输入增加几分钟，也可选择 5、10、15、30 分钟。每格最多延长到 360 分钟。
4. **收工归档**：结束今天并保存记录。也可以放弃整天，这样不会生成归档。

项目名称与图标在「设置 → 项目」中调整；默认专注时长集中在「设置 → 节奏」，使用 25、30、45、60、75、90、120 分钟等档位，可统一或按项目设置。开始页和「时间安排」中的目标按每次 15 分钟加减，也保留直接输入；学习日进行中改「时间安排」，今天的配额会跟着改，已学的进度保留。设置自动保存，单次专注时长和休息不改写默认值。

手动结束或倒计时走完后，会弹出「这段时间完成了什么？」。时间已立即计入，填写期间不再计时。记录最多 2000 字，支持换行；可以先跳过，再从「最近记录」或历史详情中补充、修改。完成内容随归档保存，也会进入复制出的 Markdown 总结；旧版任务清单仍保留在原记录中。

## 时间怎么计算（桌面）

- 学习日从「开始今天」算起，跨午夜不会自动重置。
- 一格走完或手动结束，已用时间直接计入项目进度；主动放弃的格只保留记录，不计入进度。刚开始一秒都没走就结束，不记录、也不给休息。
- 读数一律只报走满的分钟：差几十秒没满的项目不会显示成已满。
- 没有格在运行时，时间记为暂停。休息也在暂停里，但每段休息的起止会单独记下：今天页的读数分开写「已暂停」和「已休息」，时间轴把休息画成单独的一块，休息结束后也一样。
- 计时心跳中断超过 120 秒时，应用将这段空档记为自动暂停，不补算为专注时间。
- 起身提醒数的是连续在座的专注时间：两格之间停够 5 分钟（比如走完一格休息了）就从头数，停一下就接着开格不算。暂停提醒只数休息以外的暂停：休息中不催开格，休息结束后再停够设定的时长才提醒。
- **单独锁屏不会自动暂停**。如果离开座位但电脑仍在运行，需要手动暂停。

没有格在运行时，界面和菜单栏会给出「下一格」建议。今天页右上是今天这一轮月：全天目标是一轮满月，已计入的时间把它一点点照亮，每个项目都学满才是满月——一个项目超额补不了另一个项目的缺口；暂停时月亮停在原处。下方的「今日配额」每个项目一行，横条长短就是配额，骨白是已计入、朱红是正在走的这一格，配额满了的项目标着「✓ 已满」；时间轴按项目展示每段投入、休息与暂停。

## 菜单栏与提醒（桌面）

关闭窗口后，应用仍在后台运行。菜单栏菜单可以开始今天、暂停 / 继续、打开延长时间选择、结束当前格和退出。

macOS 菜单栏显示当前项目和倒计时；暂停时显示暂停时长，并在图标上标记暂停；休息时显示休息倒计时。跨小时使用 `1h05` 这样的紧凑格式，悬浮提示保留完整状态。系统菜单栏空间不足时，项目仍可能被隐藏。Windows 托盘没有标题位，倒计时显示在悬浮提示中。

项目的「短名」用于侧栏和菜单栏，可在设置中填写。留空时自动回退：能放下就用全名，否则尝试空格前的首个词，再不够则取前两个字；修改项目全名不会清掉已填写的短名。

在「设置 → 身体」开启喝水提醒后，只要应用运行，就按本地时钟在每个整点和半点提醒，例如 14:00、14:30、15:00。无需开始学习日，暂停、休息时照常提醒；启动、唤醒或系统时间回拨时不补发错过的提醒，同一钟点不重复提醒。喝水使用独立提示音（macOS 为 Pop），可在该页试听；原有杯数只保留在旧存档中。

喝水、起身护眼和暂停提醒可分别开关；暂停提醒显示本次连续暂停的总时长。声音与系统通知在「设置 → 提醒」中管理，关闭提示音也会关闭喝水声音。

## 网站屏蔽（桌面）

在「设置 → 网站屏蔽」选择规则类型：

| 类型 | 示例 | 范围 |
| --- | --- | --- |
| 精确网址 | `https://www.bilibili.com/` | 仅这个首页，其他路径的视频页仍可访问。 |
| 整个网站 | `live.bilibili.com` | 这个域名及其 `www.` 形式下的所有页面；其他子域名需单独添加。 |

精确网址保留完整路径、查询参数及片段；网址变化后可能需要另加规则。它按网址区分页面，不识别学习或娱乐内容。**如果同站还有整站规则，视频页和收藏页也会被挡住**，需先解除对应整站规则。

- **安装扩展**：在设置中打开扩展文件夹，到 Chrome / Edge 扩展管理页开启开发者模式，选择「加载已解压的扩展程序」。在主程序「设置 → 网站屏蔽」点击「复制扩展配对码」，打开坐功扩展弹窗，粘贴后点击「保存配对并同步」。每个浏览器和用户资料需分别安装、配对。
- **整站屏蔽**：系统 hosts 与扩展共同执行，写入、解除 hosts 各需要管理员授权（macOS 可装免密助手免掉，见下）。浏览器可能使用代理或旧连接，因此还需确认扩展显示「浏览器已同步」。
- **生效时段**：应用运行且学习日未结束时生效。关闭窗口到后台、暂停和休息不解除；收工、放弃今天或完整退出应用后解除。完整退出不会清空屏蔽列表，也不会丢弃未结束的学习日，重新打开后会按保存的学习日恢复规则。
- **手动解除**：需要两步确认并输入完整规则。整站规则从设置移除后，还需系统解除成功才恢复访问；取消授权时可重新应用规则。
- **核对规则**：「核对整站规则」只读比较系统规则与当前设置，不弹出授权。

### 免掉整站屏蔽的密码框（macOS）

每次开学习日要往 `/etc/hosts` 写屏蔽规则，收工要删掉，这个文件只有 root 能写，所以各弹一次密码框。
规则没有变化时不会弹。想彻底免掉，可以装一个助手：

```
sudo scripts/install-hosts-helper.sh
```

从安装包装的应用没有仓库目录，脚本随应用一起打包，路径是
`/Applications/Sitzfleisch.app/Contents/Resources/scripts/install-hosts-helper.sh`。

它把一个只有 root 能改的脚本装到 `/usr/local/libexec/sitzfleisch-hosts-install`，
并在 `/etc/sudoers.d/sitzfleisch` 写一条只放行这一条命令的免密规则。助手不接受参数，
新的 hosts 内容从标准输入读入，写之前校验每一行只能是空行、注释或「地址 + 主机名」的记录。
安装器先把助手复制到私有临时目录，核对内置 SHA-256 后才执行自检；安装也使用同一份已验证副本。源码被改动时会在执行前拒绝。可先运行 `sh scripts/install-hosts-helper.sh --check`，这条命令不提权、不安装。

**代价**：装好之后，以你的账号运行的任何程序都能免密改写 hosts 记录，不再逐次问你。
校验把影响限制在域名解析这一层，但这确实比每次输密码弱。还原：

```
sudo scripts/install-hosts-helper.sh --uninstall
```

助手没装、被删或规则失效时，应用自动回到原来的授权弹窗，不会因此失败。应用只用与当前版本逐字相同的助手；装的是旧版（例如早期没有锁定命令搜索路径的版本）时同样回到授权弹窗，重新运行上面的安装命令即可换成新版。

扩展约每 30 秒尝试同步，导航事件也会先检查连接。检测到主程序不可达或请求超时后停止拦截，并尝试恢复已有屏蔽页；重新连接后按最新学习日状态恢复。系统休眠和浏览器调度可能延后定时检查，点击扩展的「立即同步」可以主动检查。浏览器拦截发生在导航之后，页面可能短暂显示；它不保证阻止网络请求。Safari 暂不支持精确网址屏蔽。

本次安全修复需要同时更新主程序与扩展 **1.4.0**，然后按上面的步骤配对。旧版主程序或扩展没有身份验证，不能连接新版。主程序重启仍保留配对；「重新生成配对码」会使原配对失效，各浏览器需重新配对。未配对或身份验证失败时不会执行旧缓存规则。

完整匹配规则、安装步骤、权限和同步边界见[扩展使用说明](../browser-extension/README.md)。

## 历史与数据

收工后可在历史页查看项目进度和每格记录，复制当天的 Markdown，或永久删除某一天。历史最多保留 60 个学习日。页首的月历展示最近 10 周（手机上为 6 周），每天一轮当天的月亮：学满目标的是满月，没学满的暗一档，最早一条记录以来没有记录的日子是一轮没亮的新月；点一轮月可展开那一天。

记录与设置只保存在本机；浏览器扩展只通过本机回环地址读取规则。状态文件位置：

- macOS：`~/Library/Application Support/com.snooze26h.sitzfleisch.x/state.json`
- Windows：`%APPDATA%\com.snooze26h.sitzfleisch.x\state.json`
- Android：应用私有目录中的 `state.json`，正式包通常为 `/data/user/0/com.snooze26h.sitzfleisch.x/state.json`；调试包使用 `.debug` 包名。卸载即删除，两个包的数据独立。

### 保存失败时

磁盘写入失败时，今天、历史、设置页顶部会显示原因，并提示改动仍在内存里。点击「立即重试」可重新保存；之后任何一次保存成功都会清除提示。

从应用菜单「退出 坐功」（含 ⌘Q）或菜单栏图标退出时，如果保存失败，应用会停留并提供「重试并退出 / 不保存退出 / 留在这里」。

正常退出前会清理坐功写入的系统 hosts 规则；其他程序和用户自己的条目一个字节都不动，hosts 里本来就没有坐功的规则时不会请求授权。若需要管理员授权，请完成授权；取消或清理失败时应用会停留，提供「重试并退出 / 仍然退出 / 留在这里」。选「仍然退出」时，系统里的整站规则会留到下次打开坐功再解除。

**macOS 的 Dock 右键退出、AppleScript `quit` 和注销不经过这层确认。** 应用会在进程结束前补存并尝试清理系统规则，但无法保证保留窗口供失败后重试。强制结束进程不会执行退出清理，hosts 可能残留；重新打开应用后会按保存的学习日重新核对。若磁盘仍无法写入，未保存的改动仍可能丢失。

状态文件损坏、无法读取或来自更高版本时，应用进入保护模式，不覆盖原文件；本次运行的改动不会保存。

## 已知限制

- Windows 尚未完成真机验收。
- 真实合盖与唤醒后的原生界面表现尚未验收；已有计时中断验证使用冻结进程复现。
- 浏览器屏蔽尚未在用户真实 Chrome / Edge 登录会话中完成全面验收；解除后的浏览器连接和 DNS 缓存可能延后恢复。
- 系统 hosts 默认每次写入和解除都需要授权；macOS 的免密助手是可选项，装了才免，未在其他机器上验收。

已有验证范围与记录见[开发文档](development.md#已有验证记录)。
