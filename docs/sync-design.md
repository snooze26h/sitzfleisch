# 跨设备同步实现约定

本次目标：Mac 与 Android 使用同一账号，共享项目、计划、当前学习日、专注计时、完成内容和历史。共享模式按墙钟计时，合盖或锁屏不自动暂停；未登录的单机行为保持原样。

## 架构与边界

- `core/`：共享数据投影、稳定记录标识、输入校验、历史合并和冲突判断；不发网络请求。
- `src-tauri/`：Supabase 邮箱验证码登录、原生凭据存储、HTTP 同步、账号数据隔离、持久化和平台通知更新。
- `src/`：账号入口、迁移预览、同步状态、重试和冲突选择。访问令牌、刷新令牌不进入 WebView、日志或普通存档。
- `supabase/`：数据库迁移和数据库契约测试。只允许当前登录用户读写自己的文档；写入经版本比较和操作去重的事务执行。
- 不创建云端项目、不部署、不读取或上传现有个人存档。测试使用独立临时目录和合成数据。

采用共享文档的事务版本控制：文档内部的学习日和专注格具有稳定标识，按记录合并历史；不直接同步设备的 `state.json`。共享文档只含共享字段，设备的屏蔽名单、权限、提示音、提醒设置和提醒去重状态不上传。

## 文档与计时

`SyncDocument` 的协议版本 `schema = 1`，字段为 `preferences`（共享偏好）、`last_tick`、`day`、`history`、`deleted_day_ids`。核心学习日、专注格和台账增加可选的 `sync_id`；旧存档首次进入同步时分配并持久保存标识。专注格结算后将同一标识带入台账。

共享偏好只包含 categories、profiles、break_minutes、uniform_block_minutes、default_profile_id。其他偏好和提醒游标保留在设备上。远端数据必须先校验类型、数量、字符串长度、数值和记录标识；损坏/未知版本拒绝应用。

云端保存用户操作后的时间锚点，不上传每秒跳动。客户端以同一锚点按墙钟投影。自然到时可在各端确定性投影，但同一个专注格的 ID 不变，因此不会重复结算。联网时利用服务端时间校准投影；断网可以继续本机计时，但跨设备接力必须联网。

校准后使用包括系统睡眠的连续时钟（Mac `mach_continuous_time`、Android `CLOCK_BOOTTIME`、Windows `GetTickCount64`），避免系统改钟改变正在运行的进度。账号保存时记录当前有效墙钟偏移供重启恢复；每次服务端回复均从业务草稿重新投影。系统提醒的截止点在平台边界换算为设备墙钟。

首版联网同步采用有界短轮询和操作后唤醒，恢复前台立即补拉；安卓后台受系统限制，不能承诺后台实时到达。收到远端状态后更新原生通知/闹钟和桌面屏蔽状态。

## 并发与恢复

- 只有业务操作产生待上传修改；心跳和本机提醒不产生新云端版本。
- 界面和托盘操作绑定账号及用户所见的学习日/计时身份；旧确认框不能操作另一端新开的格。整份偏好编辑检查版本，完成笔记检查稳定记录 ID 与原备注；自身上传确认不会使同一计时的操作无故失效。
- 写请求具有持久化 `operation_id` 和 `expected_revision`。服务器串行比较版本，并记录已处理操作；重复请求不重复执行。客户端不能绕开 RPC 直接修改表。
- 网络请求期间不持有计时状态锁。发送中的文档固定，后续本地操作另存为草稿；确认只清除对应的请求，不能清掉后来操作。
- 版本冲突进行三方比较（共同基线、本机、云端）。不同历史记录可合并；同一学习日或同一记录两边都有实质变化时，停止自动覆盖并展示冲突。
- 用户选择本机或云端之前，保存两份完整的恢复副本。选择只决定冲突部分，独立历史仍合并；删除标记参与合并，防止已删除记录复活。
- 自动淘汰的本地历史不等同于用户删除。共享历史设明确容量上限，超限报错并保留原数据，不静默截断。
- 登录账号使用独立数据文件；退出回到原单机存档。不同账号之间不自动迁移数据。
- 账号状态、基线、草稿和未确认请求与该账号的计时状态写入同一原子存档；写失败时不上传未持久化操作。

## Supabase RPC 契约

所有时间均为 Unix 秒，版本为非负安全整数；所有标识使用有界 ASCII 字符串，操作 ID 和设备 ID 为 32 位小写十六进制。

1. `sitz_sync_read(p_known_revision bigint default -1)`：返回对象 `{revision, document, server_time}`。无云端文档时 revision=0、document=null；版本与已知版本相同时 document=null；否则返回文档。
2. `sitz_sync_write(p_expected_revision bigint, p_operation_id text, p_device_id text, p_document jsonb)`：返回 `{applied, revision, committed_revision, document, server_time}`。成功或同一请求重试时 applied=true，committed_revision 是该操作原提交的版本；冲突时 applied=false、committed_revision=null，并返回最新文档。响应始终包含当前完整文档，便于确认丢失后的追赶。
3. 同一 operation_id 配不同文档/设备/基线必须拒绝，不能伪装成成功。账号取自 `auth.uid()`，客户端不提交 user_id。匿名角色无权调用，authenticated 只能调用这两个 RPC；原始表禁止客户端写入。
4. 文档上限 2 MiB；共享历史上限 1000 个学习日，删除标记上限 10000。输入不能包含额外的设备配置或凭据字段。

## 验收

核心测试覆盖旧数据标识迁移、设备设置隔离、跨设备计时投影、同格只记一次、历史合并、删除标记、冲突和损坏输入。集成测试用本地假 HTTP 服务覆盖登录、刷新、超时、重复提交、版本冲突、提交时继续操作、重启恢复、退出/换账号隔离。数据库测试覆盖匿名拒绝、用户隔离、直接写入拒绝、CAS、幂等和输入限制。

在隔离预览中验证桌面与手机宽度的登录、同步、待同步和冲突界面；执行受影响的 TypeScript/Rust/安全检查，尝试 Android 编译。没有真实云端项目和双设备实测前，不宣称已完成生产云端或真机验收。
